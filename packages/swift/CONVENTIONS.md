# TypeScript to Swift mapping

The rules the Swift emitter (`packages/transpiler/src/swift/`) follows and every
`expected.swift` fixture shows. They copy the Kotlin target unless Swift forbids it or
gains nothing from it; each difference says why. Swift 6 language mode.

## File

- Header: the same `// <auto-generated>` block as Kotlin, then `import AlphaTabRuntime`; a file with a `describe` also gets `import Testing` and `@testable import AlphaTab` before it, and so does a test helper without one that imports from `src/` (`ComparisonHelpers`); no `package`, no `@file:Suppress`, no `@ExperimentalContracts`.
- Swift has no packages: one module `AlphaTab`, every type at top level, names printed unqualified (`Shape`, not `alphaTab.Shape`). A generated name that shadows a stdlib type (`Comparable`) is fine inside the module; the runtime spells stdlib types `Swift.X`.
- Runtime types come unqualified from `AlphaTabRuntime` (`List<T>`, `Map<K, V>`, `TypeHelper`, `Uint8Array`), not `alphaTab.core.X`.
- Layout is idiomatic Swift, not Kotlin's: 4 spaces, `{` on the same line, `} else {`, no parentheses around `if`/`while`/`switch` conditions, one blank line between members, `case` level with `switch`.
- Doc comments copy the TS JSDoc as `/** */` minus tags (`@public`, `@param`); an empty one is not printed (Kotlin prints `/**\n */`).

## Types

- `number` -> `Double`: `x: number` -> `x: Double`. Kotlin's `Int` places stay `Int`: enum raw values, `@target int` fields, collection indices.
- `boolean` -> `Bool`, `string` -> `String`, `void` -> no return type: `clear(): void` -> `func clear()`.
- `any`, `unknown` -> `Any?`; `object` -> `Any`; `object | null` -> `Any?`. Kotlin returns `Any` for `any`; Swift keeps the `?` because `any` holds `null`.
- `T | null`, `T | undefined`, `x?: T` -> `T?`: `string | null` -> `String?`.
- String literal unions -> their base type: `'a' | 'b'` -> `String`.
- `T & {}` -> as Kotlin, param `T?`, unwrapped with `!`: `requireValue<T>(_ value: T?) -> T { return value! }`.
- `T[]`, `Array<T>` -> runtime `List<T>`; `Map<K, V>` -> `Map<K, V>`. Kotlin's primitive specialisations (`DoubleList`, `ObjectDoubleMap`) collapse into the generic ones: Swift generics are specialised, not boxed.
- `Iterable<T>` -> `any Sequence<T>`; `Iterator<T>`, `Generator<T>` -> `any IteratorProtocol<T>`; `x[Symbol.iterator]()` -> `x.makeIterator()`. A class that implements `Iterable<T>` conforms to `Sequence` (no `any` in an inheritance clause), and its `makeIterator()` returns `AnyIterator<T>` (`return AnyIterator(...)`), since `any IteratorProtocol<T>` does not conform to `IteratorProtocol`.
- `Promise<T>` return -> `async -> T`: `fetch(): Promise<number>` -> `func fetch() async -> Double`.
- Tuples -> native Swift tuples (Kotlin has none, so it uses `ArrayTuple` classes): `[number, string]` -> `(Double, String)`, `[42, 'a']` -> `(42.0, "a")`, `t[0]` -> `t.0`.
- Typed arrays -> runtime classes of the same name: `new Uint8Array(n)` -> `Uint8Array(n)`.
- Function types -> Swift function types, no labels: `(value: T) => boolean` -> `(T) -> Bool`.
- Type aliases of function types -> generic `typealias`: `type Predicate<T> = (value: T) => boolean` -> `public typealias Predicate<T> = (T) -> Bool` (Kotlin drops the `<T>`).
- An interface used as a type -> `any P`: `cmd: ShapeCommand` -> `_ cmd: any ShapeCommand` (required for protocols with associated types; written for all so one rule holds).

## Classes

- A class nobody extends -> `public final class` (Kotlin: `public class`, final by default).
- A class that is extended (Kotlin `open`) -> `open class`; its overridable members (Kotlin `open fun`) -> `open func`/`open var`.
- `abstract class` -> `open class`; abstract members get a trapping body: `abstract area(): number` -> `open func area() -> Double { fatalError("abstract") }`. Swift has no abstract classes.
- Abstract property -> `open var` whose accessors trap: `open var size: Double { get { fatalError("abstract") } set { fatalError("abstract") } }`.
- `override` only when a superclass member is overridden; never for protocol conformance (Kotlin writes `override` for both; Swift rejects it on protocol members).
- Overriding a property with a field -> a private backing store plus a computed override (Swift cannot override with a stored property): `private var __size: Double = 0.0` + `public override var size: Double { get { return self.__size } set { self.__size = newValue } }`.
- `toString()`, `equals()` -> plain methods, no `override` (Swift classes have no common root). `equals(other: object)` -> `func equals(_ other: Any) -> Bool`.
- `this` -> `self`; `super.m()` -> `super.m()`.

## Fields and constructors

- Field with initializer -> `var` with it: `x: number = 0` -> `var x: Double = 0.0`. `readonly` fields stay `var`, as in Kotlin (assigned in `init` after `super.init()`).
- Field without initializer -> its zero value if Kotlin has one (`Double` `0.0`, `Int` `0`, `Bool` `false`, optional `nil`); every other type -> implicitly unwrapped `T!` (Kotlin's `lateinit`). Swift needs every stored property set before `super.init()`, and TS runs `super()` first.
- Definite assignment `name!: string` -> `var name: String!`.
- `constructor(...)` -> `public init(...)`; no constructor -> `public init() {}` as the last member (Kotlin's `public constructor()`).
- `super(a)` -> `super.init(a)` as the first statement, as in TS: `init(_ r: Double) { super.init(); self.r = r }`.
- `override init` when the superclass has an `init` with the same parameter types: `Dog(name)` over `Animal(name)` -> `public override init(_ name: String) { super.init(name) }`.
- Parameter properties -> a field (rule above) plus `self.x = x` first in `init`; the default stays on the parameter.
- Static fields -> `static`; Kotlin's `companion object` disappears and members keep source order.
- Static constructor (TS module statements beside the default class, `static {}`) -> `private static func _staticInit()`, run once inside the runtime's `jsStaticInit` lock (one recursive lock, so other threads wait for the whole body; tests run in parallel) behind `nonisolated(unsafe) private static var _staticInitDone` (set before the body, so a re-entrant call returns) and called first in every static method and `init` (shortcut: a static field read from outside the class or an implicit `init()` does not trigger it).
- Mutable static field -> `nonisolated(unsafe) static var` (Swift 6 rejects unannotated global mutable state; alphaTab touches statics from one thread). `static readonly` of `Double`/`Int`/`Bool`/`String` -> `static let`; of any other type -> `nonisolated(unsafe) static let`.

## Methods, parameters, accessors

- Parameters have no argument label: `area(w: number)` -> `func area(_ w: Double)`, called `area(w)`. TS calls are positional.
- Exception: a record's (`IRecord`) memberwise `init` keeps labels so object literals name fields, like Kotlin's named arguments: `{ x: 1, y: 2 }` -> `Point(x: 1.0, y: 2.0)`. The arguments follow the init's parameter order (declaration order, optional ones last), whatever order the literal uses: Swift requires it. A record's required field with no zero value is a plain type (`var kind: Kind`, `var id: String`), not `T!`: its init sets it, so it satisfies a protocol that requires `Kind`. A sub-record conforms to `IRecord` through its base only, sets its own fields before `super.init` (two-phase init), and passes the base fields in the base init's order. A member that implements an interface member is `override` only when a superclass declares it.
- Optional parameter -> `T? = nil`: `maybe(x?: number)` -> `func maybe(_ x: Double? = nil)` (Kotlin prints `= 0.0` for numbers; `nil` keeps TS's `undefined`).
- Default value -> Swift default: `x: number = 10` -> `_ x: Double = 10.0`.
- Rest -> variadic: `...xs: number[]` -> `_ xs: Double...`.
- Function-typed parameters -> `@escaping` always (the emitter does not prove a closure does not escape): `_ pred: @escaping Predicate<T>`. Optional function parameters are already escaping and get no attribute.
- Generic method -> `func identity<T>(_ value: T) -> T`; constraint inline: `class MinBox<T extends Base>` -> `final class MinBox<T: Base>`. `T extends number` -> `T: IAlphaTabEnum` (alphaTab binds it only to enums; Swift cannot constrain to `Double`).
- Getter/setter pair -> computed property; the setter keeps the TS parameter name: `set value(v)` -> `set(v) { ... }`.
- Getter only -> `var x: T { get { ... } }`.
- Setter only -> getter that traps (Swift has no set-only properties): `get { fatalError("value has no getter") }`.
- Static accessors -> `static var x: T { get { ... } set(v) { ... } }`.
- Generator method (`function*`) -> runtime `generator { yield in ... }`, returning `any IteratorProtocol<T>`; `yield x` -> `yield(x)`, bare `return` -> `return`. Shortcut: the runtime runs the body eagerly (Swift has no coroutines); alphaTab's one generator (`SlurRegistry.getAllContinuations`) is finite.

## Interfaces

- `interface` -> `public protocol P: AnyObject` (class-bound, so `===` and reference semantics hold).
- `extends` -> protocol inheritance: `interface Tagged extends Named` -> `protocol Tagged: Named`.
- `readonly x: T` -> `var x: T { get }`; mutable `x: T` -> `var x: T { get set }`.
- Methods -> requirements without body or `public`: `area(): number` -> `func area() -> Double`. A requirement takes no defaults (Swift forbids them): optional parameters stay `T?` without `= nil`, and a `public extension P` adds one overload per omissible trailing parameter that passes `nil` (or the TS default): `fill(x: number, y?: number)` -> `func fill(_ x: Double, _ y: Double?)` plus `func fill(_ x: Double) { fill(x, nil) }`.
- Generic interface -> primary associated type: `interface Container<T>` -> `protocol Container<T>: AnyObject { associatedtype T ... }`; a class conforms as `: Container` (no `<T>`), `T` inferred.
- A class implementing a protocol -> `final class Label: Tagged` with plain `public var` members (no `override`).
- Discriminated unions -> one protocol plus one `final class` per member, as Kotlin.
- Object literal of such a class -> runtime `with(...)`, Kotlin's `.apply {}`: `with(ShapeCommandCircle()) { $0.kind = "shape.circle" }` (`$0` cannot clash with a local; named `with` because alphaTab has `apply` methods).

## Enums

- Numeric enum -> `public enum E: Int, IAlphaTabEnum, CaseIterable { case Up = 0 }`. Case names keep their TS spelling. `IAlphaTabEnum` (runtime) supplies `fromValue(_: Double)`; `CaseIterable` replaces Kotlin's `values`, so no companion object.
- Raw values are the folded constants (`checker.getConstantValue`): `All = Read | Write` -> `case All = 3`. Swift raw values must be literals.
- Enum member -> `E.Up`.
- Bitwise on enums works on `rawValue` and must give a `number`: `c | Color.Green` -> `Double(c.rawValue | Color.Green.rawValue)`.
- No flag enums. An enum combined with a bit operator into an enum-typed slot (a `return` of an enum-returning method, an enum-typed variable, `e &= E.X` on an enum) is refused with a Swift-only diagnostic (`errors/swift-flag-enum/`): a Swift enum holds only its declared cases, and `Flags.Read ^ Flags.Write` may be none (`fromValue` would trap at run time). Enums stay plain Swift enums rather than `OptionSet`, because alphaTab's own source keeps bit flags in plain numbers: a type-checked scan of `packages/alphatab/src` (529 files, 2026-10-27) found no enum operand of `& | ^ << >> >>>` or their compound forms outside enum initializers. Write such flags as `number`.
- `classes/enums` keeps Kotlin's `toggleFlag(f): Flags { return f ^ Flags.Read }`, so the Swift target reports that refusal there too, pinned in `classes/enums/errors.swift.txt`; its `expected.swift` still pins the rest of the file (the refused method prints as `Flags.fromValue(Double(...))`, which no build ships since the emit fails).
- `n as E` (number to enum) -> `E.fromValue(n)`; enum to number -> `Double(e.rawValue)`, once (an enum operand the transformer already converted is not converted again); an optional enum -> `e.map { Double($0.rawValue) }`.

## Expressions

- Numeric literals keep Kotlin's `DoubleSuffixPass` result minus `.toDouble()`: `(2.0).toDouble() * r` -> `2.0 * r`; `v < 0` stays `v < 0` (Swift infers `Double`).
- Number to `Int` (indices) -> runtime `(x).toInt()` (Kotlin semantics: NaN -> 0, saturating; `Int(x)` traps); a literal index prints bare: `items[0]`, `bytes[(i).toInt()]`.
- `x.length` on strings and lists -> runtime `length: Double` (UTF-16 count for strings, as JS).
- `x++`, `x--` -> `x += 1`, `x -= 1` (Swift has no `++`); as an expression value -> runtime `jsPostInc(&x)`, `jsPreInc(&x)`, `jsPostDec(&x)`, `jsPreDec(&x)` (`core/Increments.swift`), which return the JS value: `array[n++]` -> `array[(jsPostInc(&n)).toInt()]`.
- `const` -> `let`, `let` -> `var` (Kotlin uses `var` for both; Swift warns on unmutated `var`).
- Templates -> interpolation through runtime `toTemplate()` (JS number formatting: `3`, not `3.0`): `` `a=${x}` `` -> `"a=\((x).toTemplate())"`. A class instance -> `\((x).toString())` when its class declares `toString()`, else `\(jsTemplate(x))` (shortcut: prints the Swift type name where JS prints `[object Object]`; only error messages do this). A template whose interpolation prints over several lines (a statement-bodied closure) -> a multi-line literal `"""` with both delimiters at column 0, so no indentation is stripped.
- String literals -> `"..."` with Swift escapes; never raw strings.
- `===`/`==` -> `==`, `!==`/`!=` -> `!=`; when both sides are class or interface instances -> `===`/`!==` (Swift classes are not `Equatable`; TS compares objects by reference): `beat.voice !== this.voice` -> `beat.voice !== self.voice`. A `null` side keeps `==`/`!=`.
- `x!` -> `x!`; `x ?? y` -> `x ?? y`; `a?.b?.c` -> `a?.b?.c`. A `!` on a value declared non-optional (a `T[]` field, a call returning `T`) prints nothing; a value unwrapped once is not unwrapped again (`previous!.bar`, never `previous!!.bar`), and `?.` after an unwrap prints `.` (`obj!.list!.map`). A list element (`items[0]!`) is non-optional too. Inside a chain, `?.` after a member declared non-optional prints `.` (`s?.config?.clef` -> `s?.config.clef`). `m.get(k)` on a map whose values may be null -> `(m.get(k) ?? nil)`, flattening Swift's `V??` (JS gives undefined for a missing key and a stored null alike).
- Truthiness: `if (x)` -> `if TypeHelper.isTruthy(x)` (once; the shared transformer's `isTruthy(isTruthy(x))` collapses); `!!x` -> `TypeHelper.isTruthy(x)`.
- `x is T` (instanceof) -> `x is T`; narrowed use -> `(x as! T)` (Kotlin's smart-cast lowering); `x as T` that may fail -> `x as? T`.
- `typeof v === 'string'` -> `TypeHelper.typeOf(v) == "string"`; narrowed use -> `(v as! String)`.
- `new C(a)` -> `C(a)`.
- `new Array<T>(n)` -> `List<T>(n)` with an `Int` length: `new Array<number>(31)` -> `List<Double>(31)`, `new Array<string>(n)` -> `List<String>((n).toInt())` (`List<Double>(31.0)` is a one-element list).
- Reserved words get backticks: a method named `init` -> ``func `init`()``, called ``x.`init`()``. Swift keywords: `associatedtype class deinit enum extension fileprivate func import init inout internal let open operator private precedencegroup protocol public rethrows static struct subscript typealias var break case catch continue default defer do else fallthrough for guard if in repeat return throw switch where while Any as false is nil self Self super throws true try`.

## Statements

- `for (init; cond; step)` -> scope `do { init; while cond { ...; step } }` (Kotlin uses `if (true) { }`; Swift's scope block is `do`).
- `for (const x of xs)` -> `for x in xs`.
- `switch` -> `switch`; a `switch` without `default` gets `default: break` (Swift switches must be exhaustive). A switch on a field declared `T!` (no initializer, no zero value) unwraps it: `switch self.kind! {`, since a pattern cannot match an optional.

## Errors

- `throw new Error(m)` -> `throw JsError(m)` (runtime `open class JsError: Swift.Error`; Kotlin uses `kotlin.Throwable`). Classes extending `Error` extend `JsError`.
- A function or `init` is `throws` when its body throws outside a `catch`, or calls a `throws` function outside a `catch`; the emitter computes this over the whole program (`SwiftThrows.ts`; TS has no checked exceptions, Swift needs them marked). Calls to it get `try`, also inside a `do`/`catch`: one `try` in front of the statement-level expression (`return try a() + b()`, `try x = f()`), because Swift rejects `try` right of a binary operator. A closure that throws makes the call it is passed to throw (the callee must be `rethrows`, as the runtime's callback helpers such as `JsonHelperPartials.forEach` are; a generated callee gets a throwing parameter type, below). In a getter, setter or property initializer, which Swift cannot make `throws`, the call gets `try!`: it traps where JS throws.
- A protocol requirement or overridable method is `throws` when any implementation is. A function type (inline or a `typealias`) is `throws` when a throwing function value is passed as an argument of that type: a closure, a method reference (`Format.join(values, Format.print)`) or a value of another throwing function type; a call through it gets `try` and makes its caller throw. Shortcut: a function value stored in a variable or field, not passed as an argument, is not tracked.
- Setters cannot throw in Swift: a setter whose body would throw uses `try!` (above).
- `try/catch (e)` -> `do { } catch { let e = error }`; `finally` -> `defer` at the top of a `do` scope.
- `async` -> `async`, `await x` -> `await x`; with throws, `async throws` and `try await`.

## Visibility

- `public` -> `public`; `private` -> `private`; `protected` -> `internal` (Swift has no `protected`); `@internal` -> `internal`. `RewriteVisibilitiesPass` widens as it does for Kotlin.
- Protocol members carry no modifier.

## Partials

- `*Partials` (Kotlin hand-written partial files) -> Swift `extension` files in `AlphaTabRuntime`/`AlphaTab` beside the generated type; `PartialsPass` decides which members, as for Kotlin.

## Tests

- `describe('X')` -> `@Suite("X") final class X` with `init() {}` (a nested `describe('X')` becomes `final class XSuite`, so it cannot shadow a model type `X`); `it('does y')` -> `@Test("does y") func doesY() async throws`.
- Test files import `Testing`, `@testable import AlphaTab` and `AlphaTabRuntime`.
- A single `it(...)` that needs an unported module is left out by name (`createEmit(..., excludedTests)`, `<path>#<test name>`, or `<path>#<describe> > <test name>` when the bare name repeats in the file (`tests/swift-excluded-test-path/` fixture, via `excluded-tests.txt`), listed in `scripts/transpile.ts`), with its reason in `Tests/AlphaTabTests/SKIPPED.md`; the rest of its file still runs.
- `expect(a).toBe(b)` and the other chai chains -> the runtime `Expector` (port of Kotlin's `TestGlobals`), which reports through Swift Testing's `#expect`/`Issue.record`. The chains (`toBe`, `toEqual`, `toBeCloseTo`, `toThrow`, snapshots) do not map one to one onto the `#expect` macro.

## Diagnostics

- Negative fixtures (`test/fixtures/errors/`) keep one shared `errors.txt` and no `expected.swift`, as they carry no `expected.kt`: the emitter must refuse the input, so there is no Swift to compare. The Swift target reports the same listing as Kotlin and C#, because all 21 come from the shared transformer (`CSharpEmitterContext`, `transforms/`), not from a printer.
- None of the 21 is legal in Kotlin, so none needs a Swift-specific message. The `Int8Array` message names the C# runtime; Swift keeps it unchanged (its runtime has no `Int8Array` either).
- A Swift-only diagnostic goes where Kotlin accepts a construct Swift cannot express, in a new `errors/swift-<case>/` fixture checked by the Swift target alone (`fixture.test.ts` runs only Swift for a negative fixture named `swift-*`). The known ones: a setter that would be `throws` (see Errors), and an enum bit operation with an enum result (`errors/swift-flag-enum/`, see Enums).
- A positive fixture whose input Kotlin and C# accept but Swift refuses in one place carries `errors.swift.txt` next to `expected.swift`: the Swift target must report exactly that listing, and its output is still compared with `expected.swift`.
- The negative branch of `fixture.test.ts` runs `csharp`, `kotlin` and `swift`; all three must produce the same listing.

## Expression and statement details

Choices the `expressions/` and `statements/` fixtures pin that the sections above leave open.

- Number bit ops -> runtime `jsAnd`, `jsOr`, `jsXor`, `jsNot`, `jsShl`, `jsShr`, `jsUshr` (`core/BitOps.swift`), which take and return `Double` with JS's ToInt32/ToUint32 semantics: NaN and +-Infinity read as 0, values wrap modulo 2^32, shift counts are masked `& 31`, `>>>` gives the unsigned result. Swift's `Int` is 64-bit, so plain `Int` operators (Kotlin's and C#'s 32-bit `Int` mapping) would not wrap (`1 << 31` stayed positive) and `x | 0` would not truncate to int32. `(a & 0xff) | (b << 8)` -> `jsOr(jsAnd(a, 255), jsShl(b, 8))`; `a >>> 1` -> `jsUshr(a, 1)`; `~a` -> `jsNot(a)`; `x | 0` -> `jsOr(x, 0)`. The shared transformer's `Int` casts on the operands are dropped; an integer literal operand stays bare (Swift reads it as `Double`). A compound bit assignment spells the operation out: `x &= m` -> `x = jsAnd(x, m)`, `x |= 0x10` -> `x = jsOr(x, 16)`.
- `%`, `%=` on numbers -> `truncatingRemainder(dividingBy:)` (Swift has no `%` on `Double`; it has JS's sign rule): `x %= 5` -> `x = x.truncatingRemainder(dividingBy: 5.0)`.
- `x ??= y` -> `x = x ?? y`; `f ||= b` -> `f = f || b`; `f &&= b` -> `f = f && b`.
- String concatenation with a number and `String(n)` -> runtime `(n).toInvariantString()`, as Kotlin; templates keep `toTemplate()`.
- `Number(s)` -> `Double(s) ?? Double.nan`. Shortcut: misses JS's whitespace trimming and `Number("") == 0`; move to a runtime helper when a caller depends on them.
- `k in o` -> ``TypeHelper.`in`(k, o)``; `e instanceof Error` -> `e is JsError`; `v instanceof Map` / `Set` -> `v is any _AnyMap` / `_AnySet` (a runtime marker every `Map` and `Set` conforms to: `is Map<Any, Any?>` misses a `Map<String, Any?>`).
- A narrowing cast to a non-optional type -> `as!` (Kotlin's `as` also throws): `item as SpecialItem` and `<SpecialItem>item` -> `(item as! SpecialItem)`; an upcast -> `(item as BaseItem)`. A value declared `unknown`/`any` is never an upcast, even where TS narrowed it (`instanceof`): `expected as Map<string, unknown>` -> `(expected as! Map<String, Any?>)`. A cast the transformer adds from `T[]` to `(T | undefined)[]` -> `List<T?>(widening: x)` (a copy: Swift classes are invariant, so `as!` would trap; shortcut: a callee that mutates it no longer changes the caller's array). `as?` only where the target is optional.
- A nullable local narrowed by a `=== null` check -> `!` at the use (Swift does not smart-cast): `return mode` -> `return mode!`. The same for a `T | null` getter TS narrowed (the shared smart cast covers fields only): `!lazy.value || lazy.value.x` -> `... || lazy.value!.x`.
- `this.m.bind(this)` -> `self.m`.
- Array literal -> runtime variadic init: `[1, 2, 3]` -> `List<Double>(1.0, 2.0, 3.0)`; `[]` -> `List<Double>()`. An array literal passed as an `Iterable` -> a Swift array literal: `new Set<number>([0])` -> `Set<Double>([0.0])`, `new Map([[k, v]])` -> `Map<K, V>([(k, v)])` (runtime `Map` builds from a sequence of tuples and iterates `(key, value)` tuples, so `for (const [k, v] of m)` -> `for (k, v) in m`). `arr?.[i]` -> `arr?[(i).toInt()]`.
- `Record<K, V>` -> runtime `Record<K, V>`; an object literal of it -> `Record<String, Double>(("alice", 95.0), ("bob", 80.0))`.
- Regex literal -> `TypeHelper.createRegex("\\d+", "")`, typed `RegExp`, as Kotlin.
- `E[e]` (enum to name) -> `String(describing: e)`; `E[s as keyof typeof E]` -> `TypeHelper.parseEnum(s, E.self)` (Swift cannot write `parseEnum<E>(...)`).
- `value as number` from `unknown` -> `TypeHelper.unknownToNumber(value)`; `value as bigint` -> `TypeHelper.unknownToInt64(value)`; `value as T[]` -> `TypeHelper.unknownToList(value, T.self)` (the same list when it is a `List<T>`, else an element-cast copy: JSON lists are built as `List<T?>` or `List<Any?>`); the same for any value declared `unknown` or `any` (a call result, an `any` lambda parameter, `v!`, or one TS narrowed with `typeof v === "number"`), since Swift keeps it `Any?`.
- `a === b` with both sides `Any?` (declared `unknown`/`any`, or cast to `any`/`undefined`) -> `TypeHelper.strictEquals(a, b)` (`!==` negated): Swift has no `==` on `Any?`. Primitives by value (NaN unequal), class instances by reference.
- `new Promise<T>(resolve => ...)` -> `await TypeHelper.createPromise({ (resolve: @escaping (T) -> Void) in ... })` inside an `async` function.
- Arrow functions and `function` expressions -> closures with typed parameters and return: `x => x * 2` -> `{ (x: Double) -> Double in return x * 2.0 }`, closed with `})` when an argument.
- Local `function` -> nested `func`, parameters unlabelled.
- Destructuring of a tuple -> tuple patterns: `const [a, b] = pair` -> `let (a, b) = pair`; `const [first] = items` -> `let (first, _) = items`; `[a, b] = [b, a]` -> `(a, b) = (b, a)`.
- `do { } while (c)` -> `repeat { } while c`.
- In a lowered C-style `for`, the step goes before every `continue` that targets that loop, including one inside a `switch` (as Kotlin); a `switch` case body needs no trailing `break`.
- `switch` on a number -> `case 0.0:` patterns.
- `try { } finally { f }` -> `do { defer { f } ... }`; with a `catch`, the `do`/`catch` nests inside that scope after the `defer`. A bare `catch` -> `catch { }` with no `let e`.
- `using r = x` -> `let r` plus `defer { r.dispose() }` right after it. `await using` -> only the binding, as Kotlin: Swift's `defer` cannot `await`. Shortcut: the async dispose never runs; give it a `do`/`catch` lowering when alphaTab uses `await using` outside tests.
- No `expressions/` or `statements/` case needs a Swift-only diagnostic: each construct Kotlin accepts there has a Swift form above.
